# pi-bigmodel

npm-имя пакета — `@rarogcmex/pi-bigmodel`.

Провайдер [BigModel / Zhipu AI](https://open.bigmodel.cn) (GLM-модели: GLM-5.3, GLM-5.2, GLM-5.1/5/5-Turbo, GLM-4.7/4.6/4.5, VLM GLM-5V-Turbo / GLM-4.6V / GLM-4.5V и бесплатные flash-модели) для [pi](https://github.com/earendil-works/pi).

> **In English.** pi-bigmodel registers **BigModel / Zhipu AI**'s China endpoint
> (`open.bigmodel.cn`) as a native pi provider under the id `bigmodel`: a curated
> GLM catalog (24 ids — text and vision), prices taken from the CNY rate card and
> converted to pi's USD `ModelCost`, real GLM thinking semantics, `/login`, an
> additive `GET /models` overlay, and **two wire protocols**: the OpenAI
> **Responses** API (`/api/v1/responses`, the default) and chat **completions**
> (`/api/paas/v4/chat/completions`, `BIGMODEL_PROTOCOL=completions`). They differ
> in one way that costs money — see «Два протокола». Install with
> `pi install git:github.com/RarogCmex/pi-bigmodel@main`, authenticate with
> `/login bigmodel` or `BIGMODEL_API_KEY`. It exists alongside pi's built-in `zai`
> provider, which targets the *international* endpoint and bills in USD — see
> «Зачем это, если в pi уже есть `zai`» below. The rest of this README is in
> Russian. Note that this plugin's user-facing runtime strings are also Russian,
> including the message that replaces the gateway's opaque Chinese 401; that is a
> deliberate language choice, not an oversight, and § Авторизация below says so
> explicitly so a non-Russian user is not surprised.

Регистрирует `bigmodel` как first-class pi-ai провайдер:

- курируемый каталог CN-эндпоинта с ценами, пересчитанными из юаней (прайс [docs.bigmodel.cn](https://docs.bigmodel.cn/cn/guide/start/pricing));
- два wire-протокола на одном ключе: **Response API** (`/api/v1/responses`) по
  умолчанию и chat completions (`/api/paas/v4`) через `BIGMODEL_PROTOCOL`;
  сравнение замеров — в «Два протокола»;
- настоящая семантика GLM-размышлений: `thinking: {type}` + `reasoning_effort` (только GLM-5.2/GLM-5.3), у действительно принудительно думающих моделей «off» скрыт — эндпоинт отвечает 400/1210;
- `/login` с подсказкой и ссылкой на страницу ключей;
- аддитивная live-дискавери-надстройка из `GET /models` (новые GLM подхватываются без правки каталога,prices кураторского каталога всегда выигрывают);
- понятные сообщения вместо китайских ошибок: 401 (`身份验证失败`), переполнение
  контекста (400/1261) и «постоянные» 429 — нулевой баланс, исчерпанный лимит,
  чужой тариф;
- лимиты изображений из документации CN-эндпоинта в `Model.inputLimits`, чтобы pi
  ресайзил картинку до отправки.

**Зачем это, если в pi уже есть провайдер `zai`.** Встроенный `zai` смотрит на
международный эндпоинт и тарифицируется в долларах. Этот плагин — для
китайского `open.bigmodel.cn`: ключ и баланс в CNY, цены из китайского прайса,
совместимые с ним compat-флаги, а также id, которых нет ни во встроенном
каталоге, ни в ответе `GET /models` (бесплатные flash-модели и VLM). Оба
провайдера можно держать включёнными одновременно — это разные `provider id`.

Стриминг, tool calls, учёт usage/cost делегированы встроенной `openAICompletionsApi` из pi-ai — это тот же протокол, что у встроенного провайдера `zai` (международный endpoint), с compat-флагами, проверенными на живом CN-эндпоинте (2026-09-24).

## Установка

```
pi install git:github.com/RarogCmex/pi-bigmodel@main
# или локально
pi install /path/to/pi-bigmodel
```

## Авторизация

1. `/login bigmodel` — ключ сохраняется в `~/.pi/agent/auth.json`;
2. или `export BIGMODEL_API_KEY=xxxxxxxx.yyyyyyyy`.

Ключи создаются на [open.bigmodel.cn/usercenter/proj-mgmt/apikeys](https://open.bigmodel.cn/usercenter/proj-mgmt/apikeys). Формат — `id.secret`; ключ с хвостовым переводом строки отклоняется так же, как отозванный, поэтому обе ветки обрезают пробелы.

При 401 (ключ истёк/отозван) `message_end` переписывает китайское сообщение в
понятное, а `turn_end` добавляет постоянную запись с ссылкой и подсказкой
`/login bigmodel` (только в интерактивном TUI: в print/json-режимах
`ctx.hasUI === false`, и запись не добавляется — иначе она скрыла бы текст ошибки
из вывода `pi -p`, где проверяется «последнее сообщение — ассистент»).

То же сделано для «постоянных» 429 — нулевой баланс (1113), исчерпанный лимит
окна (1308/1310/1316–1321) и проблемы тарифа (1309/1311/1314/1315): сообщение
объясняет причину и даёт ссылку, а специальный тег гасит ретраи, которые здесь
бессмысленны (см. «Ошибки шлюза и что делает pi»). Обычный троттлинг
(1302/1305/1313) не трогается — его pi ретраит сам.

Ключ и баланс — разные вещи: ключ с нулевым балансом проходит `/login` и
`GET /models`, но на платных моделях отвечает 429/1113. Бесплатные id
(`glm-4.7-flash`, `glm-4.5-flash`, `glm-4-flash-250414`, `glm-4.6v-flash`,
`glm-4.1v-thinking-flash`) работают и без денег — проверено 2026-10-09.

> **Язык сообщений.** Обе эти строки — на русском (`errors.ts`, `index.ts`), как и
> весь README. Заявленная цель — заменить непрозрачную китайскую 401 на сообщение,
> которое называет причину и путь решения; для русскоязычного пользователя это
> работает, для остальных замена получается столь же непрозрачной, только на другом
> языке. Это осознанный выбор языка плагина, а не недосмотр: метаданные пакета
> (`description`, `keywords`) и комментарии в коде при этом английские. Если вам
> нужен английский рантайм — это отдельная задача, и начать стоит именно с
> `errors.ts` и `index.ts`, потому что это вывод пользователю, а не документация.

проходит (200) и размышления действительно выключаются (`reasoning_tokens: 0`,

появилась «轮级思考» (пошаговое (per-turn) включение/выключение), описанная в
`capabilities/thinking-mode.md`; проза в `capabilities/thinking.md` по-прежнему
называет обе модели 强制思考. Здесь расхождение между двумя страницами доков, и
прав тот ответ, который даёт шлюз: «off» для них снова доступен в pi.

ответ всё равно приходит с блоком `<think>` внутри `content` — ни
`reasoning_content`, ни `reasoning_tokens` у этой семьи нет (замерено
2026-10-09). Поскольку «выключить» нельзя, pi не предлагает «off», а размышления
видны как обычный текст ответа.

### Лимиты изображений

Все 9 vision-id несут `Model.inputLimits` с лимитами, которые документирует сам
CN-эндпоинт (`openapi.json` → `VisionMultimodalContentItem`, прочитано
2026-10-09): ≤5 МБ на изображение, ≤6000×6000 px, jpg/png/jpeg; для семей
GLM-5.3-Flash / GLM-5V-Turbo / GLM-4.6V / GLM-4.5V — не более 50 изображений на
запрос (у GLM-4.1V-Thinking количество не опубликовано, поэтому
`maxPerRequest` там не задан).

pi трактует `maxBytes` как размер **base64**-полезной нагрузки
(`pi/dist/utils/image-resize-core.js`: «4.5MB of base64 payload»), поэтому в
каталоге стоит 5 000 000 — декодированный файл остаётся меньше документированных
5 МБ при любой трактовке. Профиль ресайза намеренно равен документированному
потолку (6000×6000), а не дефолту pi (2000×2000): GLM-5.3-Flash продаётся под
скриншоты и GUI-задачи, и даунскейл до 2000 px уничтожает мелкий текст
интерфейса. Обратная сторона — крупные изображения стоят больше входных токенов;
переопределить профиль можно в `~/.pi/agent/models.json`
(`inputLimits.images.resize`).

Раньше в `catalog.ts` лежала `IMAGE_LIMITS_BY_ID` с числами из встроенного
каталога z.ai (2000×2000, 4 718 592) — и она не была подключена ни к одной
модели, то есть pi всегда применял свой дефолт. Сейчас лимиты берутся из
документации CN-эндпоинта и реально доезжают до `Model.inputLimits`
(тест «image models publish the documented CN input limits»).

### Намеренно не включены

- `glm-4v-flash` (16K/1K — бесполезен для агента), `glm-4-long` (1M, но вывод 4K), `AutoGLM-Phone` (20K/2K, телефонный агент);
- немодальные API: embeddings, rerank, GLM-OCR, GLM-Image/CogView/CogVideo, TTS/ASR/Realtime — не chat-completions;
- `glm-4.5` и `glm-4.5v` **включены**, хотя исчезли из `model-overview` и из
  enum'ов `openapi.json` (2026-10-09): `GET /models` по-прежнему отдаёт
  `glm-4.5`, а оба id отвечают 200 и возвращают в `model` свой же id, то есть
  молча не перенаправлены на другую модель. Прайс их тоже больше не публикует
  (остались приватные инстансы) → `¥0` + `priceNote`, как у GLM-4.6/4.5-AirX.

## Два протокола

Один ключ, два wire-протокола, регистрируется один из них (`BIGMODEL_PROTOCOL`,
по умолчанию `responses`). Все 24 id каталога доступны на обеих поверхностях
(проверено бесплатным sweep'ом: каждый id отвечает отклонением `max_tokens`, а не
`model_not_found`), потолки вывода совпадают, цены и кэш-цены одни и те же.

| | Response API (по умолчанию) | chat completions |
|---|---|---|
| эндпоинт | `POST https://open.bigmodel.cn/api/v1/responses` | `POST https://open.bigmodel.cn/api/paas/v4/chat/completions` |
| выключить размышления | **нельзя**: `reasoning.effort:"none"` (114 reasoning-токенов на GLM-4.7), недокументированное `thinking:{type:"disabled"}` (114) и `do_sample:false` (93) принимаются и игнорируются; разброс по уровням none/minimal/low/medium/high/max/xhigh — 56…118 токенов, то есть шум | **можно**: `thinking:{type:"disabled"}` → `reasoning_tokens: 0` (замерено) |
| «off» в выборе pi | скрыт у всех думающих моделей (обещать нечего) | доступен у `dynamic`-моделей |
| усилие размышления | `reasoning.effort`; у GLM-5.3 валидируется low/high/max (остальное → 400), у остальных принимается, но на объём размышлений измеримо не влияет | `reasoning_effort` у GLM-5.2 (полная шкала, `none` = не думать) и GLM-5.3 (low/high/max); младшие модели поле игнорируют |
| кэш-маршрутизация | **`prompt_cache_key`** документирован («用于集群路由，以提高缓存命中率»), pi сам заполняет его из id сессии | поля нет (отправленное игнорируется) |
| попадания в кэш в реальной сессии pi | ход 1: `in 1050 / cached 44`, ход 2: `in 10 / cached 1166`, ход 3: `in 17 / cached 1246` | ход 1: `in 754 / cached 405`, ход 2: `in 10 / cached 1230`, ход 3: `in 18 / cached 1309` |
| изображения | base64 data URL в `image_url` **строкой** читается (16×16 PNG из четырёх цветов описан верно); completions-форма `image_url:{url}` принимается с 200 и **молча теряет картинку** (`input_tokens` 16 вместо 34) — pi отправляет строку, то есть правильный вариант | `image_url:{url}` объект, base64 и remote URL |
| коды ошибок | строковые в стиле OpenAI: `insufficient_quota`, `overloaded`, `context_length_exceeded`, `model_not_found`, `invalid_request` | числовые бизнес-коды: 1113, 1305, 1261, 1211, 1210 |
| отказ авторизации | **HTTP 200** с телом `{"code":1000,"msg":"身份验证失败。","success":false}` — нужен `remediateInBandResponse`, иначе pi скажет «stream ended before a terminal response event» и уйдёт в ретраи | HTTP 401 + обычный конверт `{"error":{…}}` |
| состояние на сервере | `store` / `previous_response_id` (не используем) | нет |

**Почему Responses по умолчанию.** Это поверхность, которую Zhipu развивает
(отдельный OpenAPI-спек, `reasoning_text`-стриминг, `prompt_cache_key`,
состоятельные многоходовые вызовы, richer `GET /api/v1/models`), и адаптер pi для
неё умеет переигрывать reasoning-элементы без нашего кода.

**Что за это отдаётся.** Единственный реальный минус — на Responses нельзя
выключить размышления, поэтому «off» скрыт, а уровень `minimal` (в который pi
клампит «off») стоит воспринимать как «минимум из доступного», а не как «без
размышлений». Если экономия на размышлениях важнее — `BIGMODEL_PROTOCOL=completions`
возвращает старый протокол целиком: каталог, цены, обработка ошибок и дискавери
там те же, различаются только `api`/`baseUrl`/compat-флаги и карты уровней.

> **Решение принято осознанно (2026-10-09).** Отсутствие переключателя «off» на
> протоколе по умолчанию рассмотрено оператором и допущено: Responses остаётся
> дефолтом, «off» остаётся скрытым, даунгрейд через `BIGMODEL_PROTOCOL` —
> единственная альтернатива. Записано здесь, чтобы следующая правка каталога или
> карт уровней не начинала этот спор заново. Условие пересмотра — один замер: если
> `reasoning.effort:"none"` на GLM-4.7 когда-нибудь вернёт `reasoning_tokens: 0`
> вместо замеренных сегодня ~100, переключатель снова существует, и «off»
> возвращается удалением `off: null` из `RESPONSES_EFFORT` в `models.ts`
> (проба — `research/probe-responses-2.mjs`, Q4).

Оба протокола прогнаны живьём 2026-10-09 (`npm run live` — 41 проверка на момент
включения Response API, из них
5 новых про Responses: наличие всех id и совпадение потолков вывода, завершённый
стрим с reasoning/текстом/`cached_tokens`, ремедиация in-band 401, чтение
изображения в wire-форме pi и контрольный ход на completions).

### Протоколы и поверхности (проверено 2026-10-09)

Три состояния: «проверено и отсутствует», «есть, но намеренно не добавлено»
и «исследовано и отклонено» (последняя строка таблицы закрывала долг «не
исследовалось» до замеров 2026-10-09).

| Поверхность | Состояние |
|---|---|
| `POST /api/v1/responses` (Response API) | **реализовано, протокол по умолчанию** — детали и замеры в «Два протокола» |
| `POST /api/paas/v4/chat/completions` | **реализовано** — второй протокол, включается `BIGMODEL_PROTOCOL=completions`; спецификация `ChatCompletionTextRequest`/`VisionRequest` прочитана из `openapi.json` |
| `GET /api/paas/v4/models` | **реализовано** — аддитивная надстройка дискавери; список id читается отсюда, даже когда активен Responses |
| `GET /api/v1/models` | **есть, намеренно не используется.** Отдаёт три записи в coding-plan-формате (`glm-5.3`, `glm-5.3-flash`, `glm-5-turbo`) с **пустым** полем `id` — имя лежит в `slug`/`display_name`, — поэтому надстройку по нему не построить. Зато он подтверждает две записи каталога: у `glm-5.3` уровни размышления ровно low/high/max, у `glm-5.3-flash` модальности text+image |
| `store:true` / `previous_response_id` на Response API | **есть, намеренно не используется.** Серверное состояние многоходовости (хранение 7 дней) не нужно: pi возит историю сам. pi всегда шлёт `store:false`; что именно шлюз при этом хранит или не хранит, **не измерялось** — этот пункт про неприменимость возможности, а не про гарантию приватности |
| `POST /api/anthropic/v1/messages` (Claude-совместимость) | **есть, намеренно не добавлено.** Проверено живьём: `400 {"code":"1211","message":"[1211][模型不存在…][request_id]"}` — тот же ключ работает на базе `/api/anthropic`. Выигрыша над двумя подключёнными протоколами нет, а pi-ai ждёт для него явной карты кэша (`cache_control`), которой у BigModel нет — кэш здесь имплицитный |
| `/api/coding/paas/v4` (GLM Coding Plan) | **не наше.** Эндпоинт подписки Coding Plan; в pi 1.1.0 для него уже есть встроенный провайдер `zai-coding-cn` (тот же домен, другой путь, тарификация пакетом, свои цены в USD-каталоге pi). Этот плагин — про стандартный API с оплатой по факту. Ключи Coding Plan на нём дают 429/1315, и `errors.ts` теперь так и пишет |
| `POST /api/paas/v4/async/chat/completions`, Batch API, knowledge base, managed agents | **исследовано 2026-10-09 и отклонено.** Все четыре работают живьём, но ни одно не является поверхностью провайдера: async — поллинг без SSE (`stream` молча игнорируется, задачи привязаны к ключу); Batch — офлайн-пакка со старым списком моделей (glm-4-flash бесплатен, семейств 5.3/5.2/4.7/4.6 нет); knowledge base — отдельный продукт с молчаливой деградацией (несуществующий `knowledge_id` даёт 200 без инъекции); managed agents — облачный агентный рантайм на agent-api.bigmodel.cn, конкурент pi, а не протокол. Замеры — `research/2026-10-09-platform-services.md`, сырые тела — `evidence-2026-10-09-platform.json` |
| Web Search API (`POST /paas/v4/web_search`) + встроенный поиск в chat | **принято как сайдкар** — инструмент `bigmodel_search` (см. ниже), не как wire-протокол провайдера: standalone-поиск тарифицируется за вызов (¥0.01 std / ¥0.03 pro / ¥0.05 sogou|quark) и даёт структурированные результаты; встроенный в chat поиск на бесплатной модели синтезирует ответ с источниками за ту же плату. Оба проверены живьём 2026-10-09; то же исследование |

## Кэш контекста

Проверено заново 2026-10-09 (docs `capabilities/cache.md` + `thinking-mode.md`,
живые замеры в `research/evidence-2026-10-09.json`).

**Кэш имплицитный.** Никаких полей запроса: сервер сам находит повторяющийся
префикс (доки рекомендуют ≥500 токенов, «стабильное в начале — переменное в
конце»). Попадания возвращаются в `usage.prompt_tokens_details.cached_tokens`,
pi-ai превращает их в `usage.cacheRead` и вычитает из `input`
(`api/openai-completions.js:1165`), а каталог несёт цену попадания
(`cost.cacheRead`, ≈25–50 % от input по прайсу, у бесплатных моделей — 0).
Учёт стоимости поэтому работает без единой строчки специального кода — и это
проверено двумя способами: офлайн-тест прогоняет записанное живьём тело через
настоящий адаптер pi-ai и сверяет `usage.input/cacheRead/cost` с арифметикой
каталога (`test/wire-format.test.ts`), а живой smoke-тест трижды отправляет один
и тот же длинный префикс и печатает фактические `cached_tokens`.

**Заполнение кэша асинхронное и занимает десятки секунд.** Замер 2026-10-09,
один и тот же префикс ~2,3K токенов:

| модель | интервал | результат |
|---|---|---|
| `glm-4.5-flash` (бесплатная) | 4 с | 1-й запрос `cached=4`, 2-й и 3-й `cached=1508/1510` |
| `glm-5.3-flash` | 6 с и 25 с | `cached=0` все три раза |
| `glm-4.7` | ~3 мин после первой пары | `cached=2304/2329`, повтор `cached=2304` |
| `glm-4.7` (префикс вдвое длиннее) | 30 с | 1-й `cached=2304` (попала старая половина), 2-й `cached=4608/4648` |

То есть попадание — не лотерея, а вопрос задержки: на платных моделях префикс
становился кэшируемым через минуту-три, на бесплатной — через секунды. Вывод
старой редакции README («кэш непостоянный, похоже на шардирование») уточнён:
состояние не теряется, оно просто ещё не записано. Практический смысл для pi:
первые ходы сессии платят полную цену входа, дальше длинный системный промпт
начинает попадать в кэш сам.

**`promptCache` намеренно не задан ни у одной модели.** Доки не публикуют TTL
(хранение «限时免费», срок жизни записи не указан), а pi использует это поле ровно
для одного: `getPromptCacheTtlMs()` → `CacheWarmer`, который досылает запрос с
`max_tokens: 1` на 90 % TTL, чтобы кэш не протух
(`pi/dist/core/cache-warmer.js`). Без TTL warmer останавливается с «cache
lifetime unavailable» — то есть плагин не порождает дополнительных платных
запросов, даже когда в `settings.json` стоит `cacheWarming: "idle"`. Придумать
цифру означало бы начать платить за прогрев кэша, которым мы не управляем.
Закреплено тестом («no model declares promptCache»).

**Следствие для `showCacheMissNotices`.** pi показывает notice, когда ход
переоплатил ≥20K токенов или ≥$0.10 относительно предыдущего запроса, а
«простоем» считает паузу дольше `CACHE_TTL_MS` = 5 минут — это константа под
Anthropic (`pi/dist/core/cache-stats.js`). Для BigModel такие notice нормальны:
кэш заполняется асинхронно и без опубликованного TTL, поэтому промах после
паузы не означает, что пользователь сделал что-то не так, и заранее прогреть его
нельзя.

**Сохранённое размышление (preserved thinking) связано с кэшем.**
`thinking-mode.md`: на стандартном API режим `clear_thinking: false` отключает
очистку истории размышлений, «повышает долю попаданий в кэш» и **требует**
возвращать `reasoning_content` прежних ходов без изменений. pi-ai делает ровно
это: адаптер подписывает thinking-блок именем поля, из которого его прочитал
(`thinkingSignature: "reasoning_content"`), и при повторе той же модели
(`api/transform-messages.js`, проверка `isSameModel`) кладёт текст обратно в
`reasoning_content`. Пара «`clear_thinking:false` + реплей» поэтому согласована,
и оба её конца закреплены тестами (`test/wire-format.test.ts`: реплей для своей
модели и свёртка в текст для чужой).

**Response API добавляет `prompt_cache_key`** — единственное поле запроса,
которое на этой платформе управляет кэшем («用于集群路由，以提高缓存命中率»:
маршрутизация в один кластер, чтобы попадания случались чаще). pi заполняет его
из id сессии сам, от плагина ничего не требуется; на completions такого поля
нет (отправленное игнорируется). Замер в реальной сессии pi, три хода с
инструментами на бесплатной модели: Responses — `cached 44 → 1166 → 1246`,
completions — `cached 405 → 1230 → 1309`. То есть внутри одной сессии обе
поверхности к третьему ходу отдают в кэш ~98 % промпта, и выигрыш от
`prompt_cache_key` в этом сценарии незаметен; он должен проявляться под нагрузкой
и на длинных сессиях, где маршрутизация между кластерами чаще расходится.
Числа — из сессионных JSONL, см. `research/2026-10-09-refresh.md`.

**Хранение кэша** по-прежнему «限时免费», счётчика записи шлюз не возвращает →
`cacheWrite: 0` во всём каталоге. Если Zhipu введёт плату за хранение, менять
нужно `toCost()` в `models.ts` и колонку прайса в `catalog.ts`.

## Ошибки шлюза и что делает pi

### Компакшен

**Переполнение контекста воспроизведено живьём 2026-10-09**: промпт ~200K токенов
в модель с окном 128K отклоняётся как `400 {"code":"1261","message":"Prompt
exceeds max length"}` (отклонённый запрос не тарифицируется, поэтому проверка
бесплатна и входит в `npm run live`). Эта английская формулировка уже есть в
собственном каталоге overflow-паттернов pi-ai (`utils/overflow.js`, «z.ai CN
endpoint token overflow»), так что автокомпакшен срабатывает и без плагина;
`message_end` всё равно нормализует её в `context_length_exceeded:`, потому что
таблица кодов ошибок в документах описывает тот же код 1261 по-китайски — «Prompt 超长»,
а вот её pi не матчит. Обе ветки закрыты тестами против настоящего
`isContextOverflow` из pi-ai.

Отклонения `max_tokens参数非法：限制数值范围[1,N]` (код 1210) переполнением не
считаются — иначе компактшен срабатывал бы на клиентскую ошибку; это тоже
проверено на настоящем классификаторе. 429/частотные лимиты намеренно не
матчатся.

Там же, в `live/check.ts`, потолок вывода сверяется с каталогом по бесплатным
отклонениям: `max_tokens: 99999999` → 400/1210 с раскрытым диапазоном
(2026-10-09: glm-4.5-flash 98304 ✓, glm-4.7-flash 131072 ✓, glm-4-flash-250414
16384 ✓, glm-4.6v-flash 32768 ✓, glm-4.1v-thinking-flash 16384 ✓).

Коды — из `docs.bigmodel.cn/cn/api/api-code.md` (прочитано 2026-10-09), тела —
из живых ответов того же дня. HTTP-статус приходит снаружи, бизнес-код внутри
тела; pi показывает их как `"<status>: <body>"`.

| Код | HTTP | Что это | Что делает плагин |
|---|---|---|---|
| 1261 | 400 | `Prompt exceeds max length` — переполнение контекста | нормализует в `context_length_exceeded:` → автокомпакшен (английскую формулировку pi-ai матчит и сам) |
| 1210 | 400 | неверный параметр: `该模型始终思考…`, `max_tokens参数非法：限制数值范围[1,N]` | не трогает: это не переполнение и не auth; компакшен по такому коду был бы катастрофой |
| 1211 | 400 | модели не существует | не трогает (дискавери и так не регистрирует несуществующие id) |
| 1000/1001/1003/1005 | 401 | `身份验证失败`, нет заголовка, токен истёк, нужна 2FA | переписывает в понятную подсказку со ссылкой на страницу ключей + постоянная запись в TUI |
| **1113** | **429** | `您的账户已欠费`; live: `余额不足或无可用资源包,请充值。` | **останавливает ретраи** и объясняет, что делать |
| 1308/1310/1316…1321 | 429 | исчерпан лимит окна (5 ч / 7 дней / неделя / месяц), сброс в `next_flush_time` | то же: не ретраить, показать предел |
| 1309/1311/1314/1315 | 429 | пакет истёк / модель не открыта тарифом / ключ только для Coding Plan | то же + указание, что ключи Coding Plan живут на другом эндпоинте (`zai-coding-cn`) |
| 1302/1305/1313 | 429 | честный троттлинг: лимит аккаунта, `该模型当前访问量过大`, fair-use | **не трогает** — pi ретраит с экспоненциальной задержкой, как и должен |

**На Response API коды строковые, а отказ авторизации приходит с HTTP 200.**
Замерено 2026-10-09: пустой баланс — `429 {"code":"insufficient_quota"}` (это
слово уже есть в deny-списке pi, так что ретраи гасятся без нашего участия, а
переписывание нужно только человеку), троттлинг — `429 {"code":"overloaded"}`
(ретраибельно, не трогаем), переполнение — `400
{"code":"context_length_exceeded","message":"Prompt exceeds max length"}` (pi
матчит и код, и формулировку). Хуже всего авторизация: на плохой, отозванный или
вообще отсутствующий ключ эндпоинт отвечает **200** с телом
`{"code":1000,"msg":"身份验证失败。","success":false}`. pi стримит, SSE в этом теле
нет, и наружу выходит «OpenAI Responses stream ended before a terminal response
event» — сообщение из retryable-списка, то есть мёртвый ключ ретраится весь
бюджет, а про ключ пользователь не узнаёт ничего. Лечится обёрткой
`withGatewayErrorRemediation` (`provider.ts`): она подменяет `fetch` так, что
такое тело перевыпускается как `401 {"error":{"code":"1000","message":…}}` —
дальше работает обычный путь и обычная 401-подсказка. Узко по построению: только
статус 200, только `application/json`, только тело с `success:false` и числовым
`code`; живой SSE и проксные HTML-страницы проходят насквозь (чтение через
`clone()`). Есть живой тест, который прогоняет настоящий мусорный ключ через
настоящий шлюз и настоящую обёртку.

Про 1113 отдельно: пустой баланс приезжает как HTTP 429, а классификатор ретраев
pi текстовый и видит в `429` временную ошибку. Замер до правки — 16 секунд
бесполезных ретраев в print-режиме при дефолтных настройках (а в
`settings.json` этой машины `retry.maxRetries: 10`). pi сначала проверяет
deny-список неретраибельных ошибок (`pi-ai/dist/utils/retry.js`), и в нём есть
`billing` и `quota exceeded`, — поэтому переписанное сообщение несёт тег вида
`[billing 1113]`. Тег не украшение: это единственный поддерживаемый способ
сделать ошибку неретраибельной из расширения, и тест сверяет результат с
настоящим `isRetryableAssistantError`. После правки тот же сценарий занимает
1.1 с и печатает, куда идти и какие модели продолжают работать бесплатно.

## Цены и валюта

Источники каталога — публичные страницы Zhipu: `…/guide/start/model-overview`,
`…/guide/start/pricing`, `…/guide/capabilities/thinking` и `…/thinking-mode`,
`…/capabilities/cache`, `…/api/api-code`, `…/api/rate-limit`,
`…/update/new-releases`, плюс машиночитаемый `…/openapi/openapi.json` (полный
индекс — `docs.bigmodel.cn/llms.txt`). В комментариях `catalog.ts` те же адреса
даны с суффиксом `.md` — это не опечатка: `docs.bigmodel.cn` отдаёт по любому
такому пути машиночитаемый markdown (вместо SPA-страницы на ~950 КБ), поэтому для
сверки значений удобнее именно он. Обе формы работают.

Осторожнее всего — с enum'ами моделей в `openapi.json` и с табличками
`model-overview`: они расходятся и друг с другом, и с реальностью (GLM-4.5 и
GLM-4.5V отсутствуют в enum'ах, но работают; GLM-4.7 называется принудительно
думающим в одной странице доков и пошагово переключаемым (轮级思考) в другой). Итоговое
решение всегда за живым ответом шлюза.

Прайс BigModel — в юанях за миллион токенов, pi ожидает USD за миллион. Пересчёт по курсу `BIGMODEL_CNY_PER_USD` (по умолчанию 6.7252 — срединный рыночный курс на 2026-09-15; тот же дефолт во всех наших плагинах для китайских шлюзов, чтобы отчёты о стоимости были сравнимы). `cacheWrite: 0` — хранение кэша сейчас «限时免费».

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BIGMODEL_API_KEY` | ключ, если не используется `/login` |
| `BIGMODEL_PROTOCOL` | wire-протокол: `responses` (по умолчанию) или `completions`; принимаются и полные имена `openai-responses` / `openai-completions`, регистр и пробелы игнорируются, неизвестное значение молча возвращает к дефолту |
| `BIGMODEL_BASE_URL` | замена **базы активного протокола** (прокси, зеркало). По умолчанию `https://open.bigmodel.cn/api/v1` для Responses и `https://open.bigmodel.cn/api/paas/v4` для completions; список моделей в любом случае читается с completions-базы, а поисковый сайдкар — всегда (см. ниже). Переменная намеренно одна, и guard'а на несоответствие нет: значение подставляется дословно, поэтому completions-путь при активном Responses даст `…/api/paas/v4/responses` (404). Если нужен прокси — указывайте базу того протокола, который выбрали; две разные базы для двух поверхностей не поддерживаются |
| `BIGMODEL_CNY_PER_USD` | курс пересчёта цен |

## Поисковый сайдкар bigmodel_search

Отдельный **платный за вызов** инструмент поверх двух поисковых поверхностей
платформы (исследование — `research/2026-10-09-platform-services.md`), тем же
ключом, что и провайдер: тот, что сохранён `/login bigmodel`, иначе
`BIGMODEL_API_KEY`. Паттерн — как `alibaba_tools` в pi-alibaba-models:
инструмент зарегистрирован с экспозицией **codemode** по умолчанию — вызывается
из codemode-скриптов, но не декларируется модели каждый ход; объявление в
системный промпт добавляет одна секция при загрузке.

| action | что делает | цена |
|---|---|---|
| `search` | `POST …/web_search`: структурированные результаты (заголовок/ссылка/сниппет/источник/дата) + интент-анализ запроса | **¥0.01** (search_std) / ¥0.03 (search_pro) / ¥0.05 (search_pro_sogou, search_pro_quark) за вызов |
| `ask` | chat completions на **бесплатной** модели (`glm-4-flash-250414` по умолчанию) со встроенным `web_search`-инструментом: синтезированный ответ + источники из top-level `web_search[]` | тот же один поисковый вызов; сама модель ¥0 |

Отказ не тарифицируется. Параметры: `task` (запрос/вопрос), `engine`,
`count` (1–50, по умолчанию 5), `recency` (oneDay/oneWeek/oneMonth/oneYear/noLimit),
`domain` (фильтр по домену) и `content_size` (medium/high) — для search.

Движки Sogou/Quark и 自研-движок智谱 — главное преимущество перед встроенным
поиском pi: **китайский веб**. Замеченная особенность (измерено): search_std и
search_pro на наших запросах возвращали поля `link`/`media` пустыми — названия
и даты приходят, адреса нет; парсер это переживает, вывод не рисует пустые
строки ссылок.

**Две молчаливые деградации шлюза, от которых инструмент защищён проверкой, а
не обещанием:**

- отдельный `/web_search` на нулевом балансе отклоняется 429/1113 **до**
  валидации параметров — маппинг даёт русское сообщение с ценами и ссылкой;
- встроенный в chat поиск на нулевом балансе **не падает и не ищет**: шлюз
  возвращает 200, модель отвечает устаревшими знаниями, массива `web_search`
  в теле нет (измерено на KEY1: «最新模型 — GLM-4», без источников). `ask`
  проверяет наличие массива и при его отсутствии бросает громкую ошибку —
  непоисканный ответ никогда не выдаётся за поиск.

Управление — `/bigmodel` (меню: статус, экспозиция `codemode` / `direct` /
`deferred` / `off`, движок по умолчанию, модель для `ask`). Конфиг —
`~/.pi/agent/pi-bigmodel.json` (`searchExposure`, `searchEngine`, `askModel`);
каталог агента зеркалирует `getAgentDir` pi (env `PI_CODING_AGENT_DIR`, затем
`~/.pi/agent`, config.js:491 на pi 1.1.0). Сайдкар всегда ходит на
completions-базу (`BIGMODEL_BASE_URL` с активным Responses подставится как есть).

Тот же ключ может закончиться: сообщения об ошибке переиспользуют лексику
биллинговых подсказок провайдера, но это инструментные ошибки, а не рерайты
ходов модели.

## Почему compat-флаги заданы явно

Ситуация изменилась: **начиная с pi-ai 1.1.0 авто-детект узнаёт
`open.bigmodel.cn` как z.ai** (`api/openai-completions.js:1227`), то есть четыре
вещи pi теперь угадывает сам: `thinkingFormat: "zai"`, `maxTokensField:
"max_tokens"`, `supportsStore: false`, `supportsDeveloperRole: false`. Флаги в
`models.ts` всё равно заданы явно — вот какие из них действительно что-то меняют:

- `supportsReasoningEffort` — детект даёт `false` для любого z.ai-URL, а
  GLM-5.2 и семейство GLM-5.3 `reasoning_effort` принимают. Флаг выставляется по
  записи каталога, а не по ответу шлюза: **шлюз молча принимает поле у моделей,
  которые его игнорируют** (замерено 2026-10-09 на glm-5.1, glm-4.7,
  glm-5v-turbo, glm-4.7-flash — все 200), поэтому «приняли» ≠ «поддерживают».
  А вот ограничение GLM-5.3 на low/high/max действительно enforcement'ится:
  `medium` → 400/1210;
- `zaiToolStream: true` — детект даёт `false`, хотя `tool_stream` документирован
  (для семей GLM-5.3/5.2/5.1/5/5-Turbo/4.7/4.6) и принят живьём; у моделей вне
  этого списка поле тоже принимается молча (glm-4.5-flash, glm-4-flash-250414 —
  200), так что глобальный флаг безопасен;
- `supportsStrictMode: true` — детект с pi 0.87 даёт `false` для всех не-OpenAI
  URL (issue #9816), а `strict: true` шлюзом принимается (2026-09-24,
  перепроверено 2026-10-09). В pi 1.1.0 `strict` решается **по инструменту**:
  `resolveJsonSchemaStrictSampling(tool, supportsStrictMode !== false)` шлёт
  `strict: true`, только если инструмент сам попросил
  `constrainedSampling: {type:"json_schema"}`. Наш флаг — это разрешение: без
  него собственные constrained-инструменты pi (например `read` со
  `strict:"prefer"`) деградировали бы до нестрогой схемы;
- `supportsLongCacheRetention: false`, `supportsStore: false`,
  `supportsOpenAIGrammarTools: false` — в спецификации
  `ChatCompletionTextRequest` полей `prompt_cache_retention`, `prompt_cache_key`,
  `store` и grammar-инструментов нет. Живая проверка 2026-10-09: все три поля
  шлюз **принимает и игнорирует** (200, поведение не меняется), так что причина
  не «отклонит», а «их нет в контракте» — отправлять их значило бы обещать
  управление кэшем, которого нет.

`response_format` пи для openai-completions не отправляет вообще, а `tool_choice`
— только если его попросил вызывающий код (ядро pi не просит); шлюз, к слову,
поддерживает лишь `tool_choice: "auto"`.

**Флаги Response API** (`RESPONSES_COMPAT` в `models.ts`) выводятся из
`openapi-responses.json`, а не из догадок: `supportsStrictMode: false` — у
`FunctionTool` нет поля `strict` (инструмент, который требует strict-сэмплинг,
падает громко, а не молча деградирует: на это есть тест); `supportsLongCacheRetention`
и `supportsExplicitPromptCacheMode` — false, полей `prompt_cache_retention` и
`prompt_cache_options` в схеме нет; `supportsMaxOutputTokens: true` —
`max_output_tokens` документирован с потолком 131072; `supportsDeveloperRole:
true` — роль `developer` есть в enum'е `InputMessage` и принята живьём (pi шлёт её
для думающих моделей вместо `system`); mid-convo system messages, additional
tools, tool search и grammar tools — false, их в схеме нет, поэтому pi
докладывает поздние системные сообщения в первое. `prompt_cache_key` флага не
требует: pi заполняет его из id сессии сам.

## Разработка

```bash
node scripts/link-pi.mjs    # один раз: линкует пакеты pi из глобальной установки
npm run check               # typecheck + 176 офлайн-тестов (без сети, fetch заблокирован)
BIGMODEL_API_KEY=… npm run live   # живой smoke: все id каталога + thinking-сценарии
```

**Предварительные условия.** Node ≥ 22.19 — нижнюю границу задаёт хост: `engines.node` у pi `>=22.19.0` (измерено и на 0.87.0, и на 1.0.0). Сам
type-stripping без флага и обнаружение `.ts`-тестов у `node --test` доступны
с 22.18.

`npm install` сам по себе не даёт дерева, пригодного для тайпчека: пакеты pi
(`@earendil-works/pi-ai`, `@earendil-works/pi-coding-agent`, `@types/node`)
зависимостями не объявлены — в рантайме голый спецификатор `@earendil-works/pi-ai`
подменяет загрузчик расширений pi. Их линкует `scripts/link-pi.mjs`: скрипт сам
находит глобальную установку pi (префикс npm, nvm, pnpm, `~/.local`,
`/usr/local` или каталог, куда резолвится исполняемый `pi`) и создаёт симлинки,
на Windows — junctions. Для конкретной установки:
`PI_ROOT=/path/to/node_modules node scripts/link-pi.mjs`. Проверено на
pi 0.87.1 / pi-ai 0.87.1 / `@types/node` 22.19.19; тот же setup и `npm run check`
повторены на pi 0.99.1 / pi-ai 0.99.1 (2026-09-30), на pi 1.0.0 / pi-ai 1.0.0
(2026-10-03), на pi 1.0.4 / pi-ai 1.0.4 (2026-10-06, tsc 7.1.0-dev) и на
**pi 1.1.0 / pi-ai 1.1.0 (2026-10-09, tsc 5.9.x)** — во всех прогонах офлайн-набор
зелёный (на 1.1.0: 92/92 после wire-format и cache-тестов 2026-10-09 утром,
131/131 после подключения Response API тем же днём, 146/146 после ревью, 176/176
после сайдкара bigmodel_search (тот же день; 30 новых тестов —
`test/search.test.ts`) — все четыре
счёта одного дня, поэтому здесь с датами). Загрузка
в рантайме на 1.1.0 проверена отдельно:

- `pi --list-models` показывает те же 24 модели `bigmodel`;
- `pi -p --model bigmodel/glm-4.7-flash --tools read,bash` — полноценный ход с
  инструментом на бесплатной модели и бесплатном ключе;
- `pi -p --model bigmodel/glm-4.7:off` — «off» после реклассификации проходит;
- `pi -p --model bigmodel/glm-5.3:off` — уровень клампится в `low`, а не падает
  в 400/1210;
- путь ошибки в print-режиме: 401 (мёртвый ключ) и 429/1113 (нулевой баланс)
  печатают переписанные сообщения, причём 1113 больше не ретраится.

`npm run typecheck` зовёт голый `tsc`, а `devDependencies` здесь намеренно пусты
(`scripts/link-pi.mjs` линкует только пакеты пи), поэтому TypeScript нужен в
`PATH`: `npm i -g typescript@5.9.3` — это версия, которую пиннит CI
(`.github/workflows/check.yml`); на 7.0.2 typecheck тоже чистый (измерено
2026-09-30).

`tsconfig.paths` повторяет маппинг compat-энтрипоинта лоадера pi, чтобы тайпчек
видел то же, что видит pi.

`npm run live` требует `BIGMODEL_API_KEY` и тратит реальную квоту. Границы вывода
в нём неодинаковы: `max_tokens` 8 для sweep'а по каталогу, 16–64 там, где нужно
доказать отсутствие размышлений, 200–300 для стриминга `reasoning_content`, плюс
два заведомо отклоняемых `99999999` (отклонение не тарифицируется). Шапка
`live/check.ts` раскладывает проверки по трём классам — бесплатные по построению
(отклонения), бесплатные потому что id бесплатный, и тарифицируемые — а последний
тест печатает ledger всех 2xx, так что «бесплатно» остаётся проверяемым фактом, а
не комментарием. Прогон 2026-10-09 на ключе с балансом: 42 проверки, ~137 с,
в ledger 34 принятых (то есть тарифицированных) вызова, порядка ¥0.05 — основная
статья ход `glm-5.2` с `max_tokens: 300`; восемь остальных — отклонения, которые
не тарифицируются.

`npm run live` покрывает обе поверхности: 42 проверки, из них 5 про
Response API (наличие всех 24 id и совпадение их потолков вывода с каталогом,
завершённый стрим с reasoning/текстом/`cached_tokens`, ремедиация in-band 401
настоящим мусорным ключом, чтение изображения в wire-форме pi и контрольный ход
на completions с доказательством `reasoning_tokens: 0`). Ни одна из пяти ничего не
стоит, но по разным причинам, и разница существенна: две **бесплатны по
построению** (sweep потолков и мусорный ключ — это отклонения, они не
тарифицируются), три приняты шлюзом и прошли на бесплатных id, то есть
тарифицированы нулём. В шапке `live/check.ts` и в ledger это разделено.

Офлайн-набор запускается с `--import ./test/no-network.ts`: препроцессор
подменяет `globalThis.fetch` бросающей заглушкой и повторяет алиас загрузчика pi
(голый `@earendil-works/pi-ai` → compat-энтрипоинт). «Тесты без сети» — это
свойство набора, а не обещание в комментарии: случайный выход в интернет
(который на этом шлюзе означает списание денег) роняет тест сразу.

### Что покрыто тестами

- инварианты каталога (уникальность id, окна, полосы цен, покрытие живого `/models`);
- **поисковый сайдкар** (`test/search.test.ts`, фикстуры — настоящие тела шлюза 2026-10-09): экспозиция/движок/модель по умолчанию и деградация мусорных значений, сборка обоих запросов (клампы count/max_tokens, intent, домен), разбор std/pro/chat-ответов и пустых тел, форматирование (строки ссылок не рисуются для пустых `link`), маппинг ошибок (1113/1211/1305/401 по живым конвертам), чтение ключа из `auth.json`/env, атомарный раундтрип конфига, метаданные инструмента и end-to-end `execute` с заглушенным `fetch` — включая громкий отказ `ask`, когда шлюз молча пропустил поиск (200 без массива `web_search`, измерено на нулевом балансе), и интерпретацию `exposure=off` в `index.ts` (entry-тесты);
- конвертация CNY→USD, `cost.tiers`, compat-флаги и карты thinking для всех четырёх видов ThinkingControl (`none`, `dynamic`, `effort`, `always`);
- семейные догадки для неизвестных id (zero-cost, conservative windows, лимиты изображений);
- **Responses-поверхность** (`test/responses.test.ts`): выбор протокола и его дефолт, compat-флаги по опубликованной схеме (`FunctionTool` без `strict`, `max_output_tokens`, `developer`-роль), `prompt_cache_key` из id сессии, отсутствие `prompt_cache_retention`/`prompt_cache_options`/`thinking`, карты уровней (включая «off не предлагается никому» и «GLM-5.3 никогда не получает нелегальный effort»), форма изображений и разбор **настоящего** живого стрима из `test/fixtures/responses-stream-full.sse` (reasoning-элемент → thinking-блок с подписью, `output_text` → текст, `cached_tokens` → `cacheRead`, `response.incomplete` → length, а не error);
- **wire-format** (`test/wire-format.test.ts`): настоящий адаптер pi-ai с заглушкой `fetch` и перехватом тела через `onPayload` — URL, `max_tokens`, `stream_options`, отсутствие `store`/`prompt_cache_*`/`response_format`/`tool_choice`/`developer`, `tool_stream`, `strict` по инструменту, и матрица thinking по всему каталогу × все уровни, включая инвариант «принудительно думающая модель никогда не получает `disabled`»;
- **учёт кэша и цены**: записанное живьём тело с `cached_tokens` прогоняется через адаптер → `usage.cacheRead/input/cost` сверяются с арифметикой каталога; отдельно — что pi выбирает ценовую полосу по сумме `input + cacheRead` (так и считается «вход ≥32K»), и что `promptCache` не задан ни у одной модели;
- парсинг/мерж дискавери, деградация без сети/ключа, отмена;
- auth: `/login` (ссылка на страницу ключей, trim, отказ на пустом), resolve из env/хранилища;
- errors: overflow-нормализация (EN/CN/1261, идемпотентность, guard на rate limit, негативные тесты на двухсимвольный `超长`), 401-кларификация, классификация постоянных 429 (числовые и строковые коды), чтение собственных тегов обратно (`classifyRewritten`), разбор и ремедиация in-band 200-ошибки;
- **порядок хуков** (`test/entry.test.ts`, fake-pi): `message_end` → in-place замена сообщения (как в `agent-session.js` `_replaceMessageInPlace`) → `turn_end`, то есть turn_end видит **наш** рерайт, а не тело шлюза. Без этого теста постоянная подсказка про биллинг была недостижима: классификация по сырому телу на втором шаге уже ничего не находила, а auth-ветка выживала случайно — потому что `clarifyErrorMessage` цитирует оригинал. Теперь вид подсказки читается из тега, который вставляет сам рерайт (`[billing 1113 balance]`, `[quota exceeded 1310 quota]`), с fallback на сырое тело;
- регистрация: дефолтный протокол, `BIGMODEL_PROTOCOL=completions`, и что нераспознанное значение не молчит — и всё это против **настоящих** классификаторов pi (`isContextOverflow`, `isRetryableAssistantError`), чтобы переписывание случайно не стало ретраибельным и не запустило компакшен.

### Проверено на живом шлюзе (2026-09-24)

Флаги совместимости каталога, `thinking.type` вкл/выкл (включая ответ 400/1210 на glm-5.3), `clear_thinking:false`, `reasoning_effort`, SSE `reasoning_content`, tool calls с `tool_stream` / `strict` / `response_format`, `GET /models` (11 id) и тело 401 проверены на живом CN-эндпоинте. Редкие 429 на бесплатных flash — rate limit при серийных запросах, а не ограничение ключа.

### Перепроверено и уточнено (2026-10-09, pi 1.1.0)

Сырые тела запросов и ответов — в `research/evidence-2026-10-09.json`, скрипт
пробы — `research/probe.mjs` (`node research/probe.mjs free|paid`; ключи читает
из `secret.env`, в лог не печатаются).

Что изменилось по сравнению с сентябрьской сверкой:

1. **GLM-4.7 и GLM-4.5V больше не принудительно думающие** — `disabled`
   принимается и действительно выключает размышления. «off» вернулся в выбор pi
   (см. ‡ выше).
2. **Код переполнения известен и воспроизведён**: 400/1261 `Prompt exceeds max
   length`. Раньше в README числился «не воспроизводился дёшево».
3. **Пустой баланс — это 429/1113**, и pi ретраил его как обычный троттлинг.
   Добавлена неретраибельная подсказка.
4. **Кэш заполняется асинхронно (секунды–минуты), а не «непостоянно»**; учёт
   `cached_tokens` → `cacheRead` → стоимость подтверждён на живых числах.
5. **Шлюз молча принимает неподдерживаемые поля** (`reasoning_effort` у
   GLM-5.1/4.7/5V-Turbo, `store`, `prompt_cache_key`, `prompt_cache_retention`,
   `tool_stream` у моделей вне списка) — значит, «ответил 200» больше не
   доказательство поддержки; все такие флаги в каталоге опираются на
   спецификацию, а не на принятие.
6. **Появились два соседних протокола** (Response API и Claude-совместимость) и
   отдельный эндпоинт Coding Plan, который pi 1.1.0 закрывает встроенным
   `zai-coding-cn` — описано в «Протоколы и поверхности».
7. **Лимиты изображений** взяты из документации CN-эндпоинта (5 МБ,
   6000×6000, ≤50 штук) и наконец доезжают до `Model.inputLimits`; прежняя
   `IMAGE_LIMITS_BY_ID` с числами z.ai была мёртвым кодом.
8. **Потолки вывода** сверены с каталогом по бесплатным отклонениям на всех
   пяти бесплатных id.
9. Новых моделей с 2026-08-26 (GLM-5.3-Flash) не выходило —
   `cn/update/new-releases.md`; состав `GET /models` не изменился (11 id).

### Подключён Response API (2026-10-09)

`POST https://open.bigmodel.cn/api/v1/responses` стал протоколом по умолчанию;
completions остался и включается `BIGMODEL_PROTOCOL=completions`. Замеры, которые
это определили, — в «Два протокола» и в `research/2026-10-09-refresh.md`;
сырые тела — в `research/evidence-2026-10-09-responses.json`.

Проверено в настоящем pi 1.1.0 (чистый `HOME`, плагин через `-e`):

- ход с инструментами на бесплатной модели через Responses;
- трёхходовой цикл read → write → ответ: reasoning-элементы и tool call/result
  переигрываются корректно, файл записан;
- `glm-4.7` с уровнем high на платном ключе: `api=openai-responses` в сессионном
  JSONL, стоимость посчитана;
- кэш внутри сессии: `in 1050/cached 44 → in 10/cached 1166 → in 17/cached 1246`;
- in-band 401 (отозванный ключ) → та же русская подсказка, что и на completions;
- 429/1113 → 1.2 с вместо 16 с ретраев;
- `BIGMODEL_PROTOCOL=completions` → тот же сценарий проходит по старому
  протоколу.

Одна ложная находка, которую стоит запомнить: первая проба изображений на
Responses дала `400 图片输入格式/解析错误`, и это выглядело как «поверхность не
принимает base64». Причина была в самом фикстуре — base64-PNG был собран
вручную и невалиден. Корректно закодированный PNG в той же форме (`image_url`
строкой) читается моделью правильно, а вот completions-форма `image_url:{url}`
принимается с 200 и **молча теряет изображение** (`input_tokens` 16 вместо 34,
